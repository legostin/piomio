# open-bot — дизайн системы

Дата: 2026-10-26. Рабочее название: **open-bot**.

> **Переименования:** 2026-10-26 open-bot → Owlbot (имя open-bot оказалось занято), 2026-10-31 Owlbot → **Piomio**. Документ оставлен как есть, поэтому в нём старые имена: open-bot → Piomio, `@openbot/*` → `@piomio/*`, `OPENBOT_*` → `PIOMIO_*`, `.openbot-plugin/` → `.piomio-plugin/`, `openbot-node` → `piomio-node`, MCP-сервер `openbot` → `piomio`.

## 1. Цель

Открытая self-hosted альтернатива персональным агентам Grok Bot, Meta Muse и OpenAI Dots: проактивный агент со своим компьютером и браузером, который работает на железе пользователя и на подписках, за которые пользователь уже платит (Claude, ChatGPT), или через API любых вендоров. Безопасность — часть продукта с первого дня.

**Первый пользователь** — технари-селфхостеры, которым не страшен сервер по SSH. **Успех** — автор пользуется системой каждый день и рекомендует друзьям-разработчикам.

**Сценарии v1** (все четыре равноправны): разработка (код, PR, CI через Claude Code/Codex на машинах пользователя), личные дела (почта, календарь, сводки), ресёрч и мониторинг, браузерная рутина.

**Не цели MVP:** маркетплейс плагинов, мобильное и десктопное приложения, несколько пользователей на инстанс, голос, векторный поиск по памяти, управление личным Chrome на подключённых машинах, собственный relay для NAT.

## 2. Ключевые решения

| Решение | Выбор |
|---|---|
| Модель «мозга» | Подключаемый харнесс: Claude Code, Codex или своя петля поверх API. Платформа — «тело», отдаёт инструменты через MCP |
| Архитектура | Микроядро + плагины. Встроенные функции сами являются плагинами и используют только публичный API |
| Формат плагинов | Надмножество Claude Code (`.claude-plugin/plugin.json`) и Codex (`.codex-plugin/plugin.json`) + своя часть `.openbot-plugin/plugin.json` |
| UI-плагины | ES-модули прямо в странице (доверенный код); опасные поверхности (подтверждения, vault, правила) — на изолированном origin |
| Стек | TypeScript везде, Node.js 24, npm workspaces, SQLite (`node:sqlite`), Fastify, React 19 + Vite |
| Канал на телефон | Telegram-бот (long polling) |
| Развёртывание | Приложение для macOS и Windows и `install.sh` для сервера на Linux (Docker-образа нет); работает на домашнем сервере, VPS или рабочем компьютере |
| Сеть машин | Входит в MVP: демон `openbot-node` подключается к хабу исходящим WebSocket |

## 3. Архитектура

```
 Веб (8080)   Пульт безопасности (8081)   Telegram
     │                 │                      │ (плагин-канал)
 ┌───▼─────────────────▼──────────────────────▼───────────────┐
 │ ЯДРО (хаб)                                                  │
 │  хост плагинов · шина событий и хуки · политики · vault ·   │
 │  аудит · сессии и задачи · хранилище · MCP-шлюз ·           │
 │  egress-прокси · вход · реестр машин                         │
 └───▲───────────────▲───────────────▲──────────────▲──────────┘
     │ RPC (stdio)    │               │ MCP          │ WebSocket
  процессы плагинов  │          процессы мозгов    демоны openbot-node
  (браузер, Telegram, │          (claude, codex,    на других машинах
   триггеры, память,  │           api-петля)
   мозги)             │
```

### 3.1 Ядро (`packages/core`)

Ядро делает только то, что нельзя отдать плагинам:

- **Хост плагинов** — обнаружение, проверка манифеста, права, запуск процессов, RPC, перезапуск при падении.
- **Шина событий и хуки** — типизированные события; хуки могут изменить данные или заблокировать действие, но не могут ослабить политику.
- **Политики, подтверждения, правила** — классы действий инструментов, карточки подтверждений, правила пользователя, пометка недоверенного контента.
- **Vault** — шифрованное хранилище секретов и персональных данных.
- **Аудит** — журнал с хэш-цепочкой.
- **Сессии, задачи, переписки** — машина состояний задач, нормализованные транскрипты.
- **MCP-шлюз** — один MCP-эндпоинт на сессию мозга, только разрешённые инструменты, редакция секретов в выдаче.
- **Egress-прокси** — HTTP(S)-прокси со списком разрешённых хостов для мозгов и плагинов.
- **Вход** — пароль (Argon2id) и passkey (WebAuthn), одноразовая ссылка первичной настройки.
- **Реестр машин** — привязка, ключи Ed25519, статусы, маршрутизация на демоны.
- **HTTP/WS API** для веба, пульта и демонов.

### 3.2 Процессы и изоляция

Хаб, мозги и плагины работают от одного пользователя: на компьютере — от пользователя человека, на сервере — от `piomio` без sudo (`install.sh`). Стены: egress-прокси для всего трафика процессов, на macOS — песочница Seatbelt для собственных команд CLI-мозгов (папка агента, без сети), остальное — через подтверждения.

### 3.3 Хранилище

Всё состояние — в томе `/data`:

- `/data/openbot.db` — SQLite: переписки, сообщения, задачи, сессии, подтверждения, правила, аудит, машины, плагины, настройки, kv плагинов, триггеры.
- `/data/vault.db` — отдельная SQLite только с шифротекстами vault.
- `/data/memory/` — память (markdown + git).
- `/data/workspaces/<agent>/<task>/` — рабочие папки.
- `/data/plugins/` — установленные плагины; `/data/plugins-data/<id>/` — данные плагинов.
- `/data/skills/`, `/data/agents/` — пользовательские скиллы и агенты.
- `/data/browser/<profile>/` — профили Chromium.

## 4. Плагины

### 4.1 Структура плагина

```
my-plugin/
  .openbot-plugin/plugin.json   # наш манифест (необязателен для плагинов Claude/Codex)
  .claude-plugin/plugin.json    # если плагин из экосистемы Claude Code
  .codex-plugin/plugin.json     # если плагин из экосистемы Codex
  skills/<name>/SKILL.md
  commands/<name>.md
  agents/<name>.md
  hooks/hooks.json
  .mcp.json
  server/index.js               # бэкенд-код (отдельный процесс)
  ui/index.js                   # UI-модуль (ES-модуль в странице)
```

Плагин Claude Code или Codex без нашего манифеста ставится как есть: его `skills/`, `commands/`, `agents/`, `.mcp.json` и хуки становятся доступны мозгам.

### 4.2 Манифест `.openbot-plugin/plugin.json`

```json
{
  "id": "telegram",
  "name": "Telegram",
  "version": "0.1.0",
  "description": "Канал Telegram: уведомления, подтверждения, чат",
  "server": "./server/index.js",
  "ui": "./ui/index.js",
  "contributes": {
    "tools": true, "channels": ["telegram"], "brains": [], "triggers": [],
    "settings": { "type": "object", "properties": { "chatId": { "type": "string" } } }
  },
  "permissions": {
    "network": ["api.telegram.org"],
    "vault": ["telegram_bot_token"],
    "core": ["channels.deliver", "approvals.resolve"],
    "ui": ["panel", "statusbar"]
  }
}
```

Права подтверждаются пользователем при установке. Без объявленного права ядро отклоняет вызов. Плагины закрепляются на хэше коммита git (при установке из git); при обновлении показывается разница в правах.

### 4.3 Бэкенд плагина

Процесс плагина общается с ядром по JSON-RPC 2.0 поверх stdio (NDJSON). SDK (`@openbot/plugin-sdk`) перенаправляет `console.log` в stderr.

```ts
import { definePlugin } from "@openbot/plugin-sdk";
export default definePlugin({
  async activate(ctx) {
    ctx.tools.register({ name, description, inputSchema, effect: "read" | "local-write" | "external", handler });
    ctx.brains.register({ id, label, probe, createSession });
    ctx.channels.register({ id, send, renderApproval });
    ctx.triggers.register({ kind, start, stop });
    ctx.events.on("message.created", handler);
    ctx.hooks.on("tool.before", async (call) => ({ block: "причина" } | { input } | undefined));
    const token = await ctx.vault.get("telegram_bot_token"); // только объявленные записи
    ctx.storage.get/set/delete;            // kv плагина
    ctx.core.call("tasks.create", {...});  // API ядра в пределах прав
    ctx.log.info("...");
  },
});
```

### 4.4 UI-плагины

UI-модуль плагина — ES-модуль, который хост загружает динамически. React, ReactDOM и UI SDK общие: import map в `index.html` указывает `react`, `react-dom`, `react/jsx-runtime`, `@openbot/ui` на shim-модули, которые отдают экземпляры хоста.

```ts
export function activate(ui: OpenBotUI) {
  ui.slots.register("sidebar.panel", { id, title, icon, component });
  ui.slots.register("chat.toolResult", { match: { tool: "browser.*" }, component });
  ui.slots.override("chat.composer", WrapperComponent, { priority: 10 });
  ui.statusbar.add({ id, render });
  ui.commands.register({ id, title, run });
  ui.routes.add({ path: "/plugins/x", component });
  ui.settings.section({ pluginId, schema });
  ui.toast("...");
}
```

Именованные слоты ядра: `layout.sidebar`, `layout.statusbar`, `sidebar.panel`, `pane.right`, `live.view` (плавающее окно живого просмотра, см. `2026-10-26-live-view-design.md`), `chat.message`, `chat.toolResult`, `chat.composer`, `chat.composerActions`, `settings.section`, `route`. Каждый слот обёрнут в error boundary: упавший плагин заменяется компонентом ядра.

**Модель доверия:** UI-плагин — доверенный код с полным доступом к основной странице. Предупреждение при установке: «UI-плагин получает полный доступ к интерфейсу». Защита:
1. Подтверждения, vault, правила и аудит — на отдельном origin (порт 8081, отдельная cookie, `frame-ancestors 'none'`, открывается отдельной вкладкой). Код основной страницы не может их прочитать, нажать или вызвать их API.
2. Строгий CSP основной страницы: `script-src 'self'`, `connect-src 'self'`, `img-src 'self' data: blob:` — плагин не может отправить данные на внешний сервер из браузера.

### 4.5 Хуки

События хуков: `session.start`, `message.in`, `tool.before`, `tool.after`, `notify.before`, `task.created`, `task.done`. Порядок: хуки плагинов → политика ядра. Хук может заблокировать вызов или изменить вход; результат хука не может превратить `deny`/`ask` политики в `allow`. Хуки из плагинов Claude Code (`hooks/hooks.json`) передаются харнессу Claude Code как есть.

## 5. Мозги, агенты, задачи

### 5.1 Интерфейс мозга

```ts
interface BrainProvider {
  id: string;                 // "claude-code" | "codex" | "api" | ...
  label: string;
  probe(machine: MachineRef): Promise<{ available: boolean; authenticated: boolean; version?: string; models?: string[]; detail?: string }>;
  createSession(opts: {
    sessionId: string; agent: AgentDef; workspace: string;
    mcp: { url: string; token: string; bridgeCommand: string[] };
    systemPrompt: string; skillsDir: string; resume?: string; env: Record<string, string>;
  }): Promise<BrainSession>;
}
interface BrainSession {
  send(turn: { text: string; attachments?: string[] }): AsyncIterable<BrainEvent>;
  interrupt(): Promise<void>;
  close(): Promise<void>;
  resumeToken?: string;
}
type BrainEvent =
  | { type: "text"; delta: string }
  | { type: "tool_call"; id: string; name: string; input: unknown }
  | { type: "tool_result"; id: string; output: string; isError?: boolean }
  | { type: "usage"; inputTokens?: number; outputTokens?: number; costUsd?: number }
  | { type: "limit_hit"; resetAt?: string; detail: string }
  | { type: "error"; message: string }
  | { type: "done"; resumeToken?: string };
```

Адаптеры MVP:

- **`claude-code`** — `claude -p --output-format stream-json --verbose --input-format text`, `--mcp-config` (сервер `openbot` через stdio-мост), `--strict-mcp-config`, `--append-system-prompt`, `--resume <id>`, `--permission-mode dontAsk` с `--allowedTools` (встроенные файловые инструменты + `mcp__openbot__*`), `--setting-sources ""`. Аутентификация — только собственный вход Claude Code на каждой машине (`claude auth login` из чата или уже существующий логин); токены подписки hub не принимает и не хранит: условия Anthropic запрещают приложениям собирать и хранить их.
- **`codex`** — `codex exec --json` / `codex exec resume <id> --json`, MCP-сервер `openbot` через `-c mcp_servers.openbot.command=...`, песочница `workspace-write`. Аутентификация — логин ChatGPT на машине или `OPENAI_API_KEY`.
- **`api`** — собственная петля: провайдеры `anthropic` (Messages API) и `openai` (Chat Completions; покрывает OpenAI, OpenRouter, Ollama, LM Studio, vLLM). Инструменты — из MCP-шлюза ядра.

Сторонние мозги (Gemini CLI и другие) добавляются плагинами.

### 5.2 MCP-шлюз и мост

Хаб реализует MCP-сервер (JSON-RPC 2.0: `initialize`, `tools/list`, `tools/call`, `ping`) по HTTP `POST /mcp` с токеном сессии в `Authorization: Bearer`. Для харнессов, понимающих только stdio, — мост `openbot-mcp-bridge` (`packages/mcp-bridge`): читает JSON-RPC из stdin и пересылает в хаб, URL и токен — из переменных окружения.

Токен сессии короткоживущий, привязан к сессии, агенту и набору разрешённых инструментов.

### 5.3 Отложенное выполнение внешних действий

Инструмент класса `external` без разрешающего правила создаёт подтверждение и ждёт ответа до 60 секунд. Если ответа нет, мозгу возвращается `{"status":"awaiting_approval","approvalId":"…"}` с инструкцией закончить ход. После одобрения ядро само выполняет действие и отправляет результат в сессию новым ходом. Так долгие ожидания не упираются в таймауты MCP у харнессов.

### 5.4 Агенты

Агент — файл `agents/<id>.md` с frontmatter (совместим с сабагентами Claude Code):

```markdown
---
name: assistant
description: Главный ассистент
brains: ["claude-code@local", "codex@local", "api:anthropic"]
model: sonnet
initiative: 1
tools: ["*"]
skills: ["*"]
policyProfile: default
budget: { backgroundRunsPerDay: 30 }
---
Ты — дружелюбный и проактивный ассистент…
```

По умолчанию есть агент **assistant**. Пользователь создаёт агентов в вебе или файлами в `/data/agents/`.

### 5.5 Задачи и переписки

- **Переписка (conversation):** главный тред с ассистентом + треды задач. Веб и Telegram показывают один и тот же тред.
- **Задача:** `id, conversationId, parentTaskId, agentId, title, goal, status, brainRef, resumeToken, createdBy (user|agent|trigger), createdAt, updatedAt, result`. Статусы: `queued → running → (waiting_approval | waiting_input | interrupted) → done | failed | cancelled`.
- **Делегирование:** инструмент `task.delegate({agent, goal})` создаёт дочернюю задачу; результат приходит сообщением в родительскую переписку.
- **Параллельность:** лимит одновременных сессий на пару «мозг@машина» (по умолчанию 2).
- **Переключение мозгов:** при `limit_hit`, отсутствии логина или офлайн-машине задача переходит к следующему мозгу из списка агента со сводкой из нормализованного транскрипта ядра либо ставится на паузу до `resetAt`.

## 6. Безопасность

**Модель угроз:** prompt injection из страниц, писем и документов; вредоносный или кривой плагин, скилл, MCP-сервер; инстанс, открытый в сеть; мозг, делающий лишнее своими инструментами; украденная машина с демоном.

### 6.1 Vault

- Ключ шифрования данных (DEK, 32 байта) обёрнут ключом, выведенным из пароля vault через Argon2id (`@noble/hashes`, m=64 МиБ, t=3). Записи шифруются XChaCha20-Poly1305 (`@noble/ciphers`).
- После старта vault «запечатан» до разблокировки на пульте (8081). Автоматическая разблокировка — через файл `PIOMIO_VAULT_PASSPHRASE_FILE`.
- Типы записей: `login` (url, username, password, totp), `secret` (API-ключ/токен), `identity` (персональные данные: поля «ключ-значение»), `note`.
- У каждой записи область: `domains` (для подстановки в браузере), `plugins`, `agents`, `tools`, режим `auto | ask`, флаг `revealToModel` (по умолчанию `false`).
- Модель видит только ссылки `vault://<id>`. Подстановку делает ядро или плагин с объявленным правом.
- **Редакция:** все значения vault (и их base64/url-encoded варианты) вырезаются из результатов инструментов, транскриптов, сообщений каналов и логов.

### 6.2 Политики и подтверждения

- Каждый инструмент объявляет класс: `read`, `local-write`, `external`. Внешние MCP-инструменты получают класс из аннотаций (`readOnlyHint` → `read`, иначе `external`).
- Решение политики: `allow | ask | deny`. По умолчанию `read`, `local-write` → `allow`, `external` → `ask`.
- Карточка подтверждения: инструмент, агент, задача, точный вход (адресат, текст, домен, сумма). Ответы: «один раз», «всегда для такого» (правило), «нет».
- **Правила** создаются только на пульте или через Telegram пользователем. Правило: `tool` + условия на поля входа (равенство, шаблон, домен) + `agent?` → `allow | deny`.
- **Недоверенный контент:** сессия, получившая результат инструмента-источника (`browser.*`, внешний MCP, `web.fetch`, почта), помечается `tainted`. В помеченной сессии правила `allow` не действуют для адресатов и доменов, которых нет в истории одобрений.
- Фоновые задачи агентов с инициативой `1` получают только инструменты класса `read` плюс `notify`.

### 6.3 Изоляция

- Пользователи Unix (п. 3.2), `sudo -u` с узкими правилами.
- **Egress-прокси** ядра (HTTP CONNECT) со списками разрешённых хостов: для мозгов по умолчанию — API вендоров, реестры пакетов, GitHub; для плагинов — объявленные `permissions.network`. Процессам задаются `HTTP_PROXY/HTTPS_PROXY`.

### 6.4 Сеть и вход

- По умолчанию хаб слушает `127.0.0.1`. При `OPENBOT_HOST` не-локальном адресе без настроенного пароля хаб не стартует.
- Первый вход — одноразовая ссылка из логов → установка пароля → (опционально) passkey.
- Проверка `Host` по белому списку (`OPENBOT_ALLOWED_HOSTS`), проверка `Origin` для изменяющих запросов и WebSocket, cookie `HttpOnly; SameSite=Strict`, CSRF-токен.
- Сессия пульта (8081) отдельная от основной.

### 6.5 Машины

- Привязка: одноразовый код из веба → демон генерирует ключ Ed25519 → хаб сохраняет публичный ключ. Аутентификация — подпись challenge при каждом подключении.
- Демон сам проверяет локальную политику `~/.openbot-node/policy.json` (разрешённые папки, команды, мозги); файл правит только владелец машины.
- Отзыв машины в один клик.

### 6.6 Аудит

Таблица `audit` с хэш-цепочкой (`hash = sha256(prevHash + record)`): вызовы инструментов, решения политики, подтверждения, обращения к vault, установка плагинов, изменения правил и политик, вход. Просмотр и проверка целостности — на пульте.

## 7. Проактивность

### 7.1 Триггеры (плагин `triggers`)

- **`schedule`** — cron в часовом поясе пользователя.
- **`watch`** — опрос URL/RSS/JSON с детерминированным сравнением (хэш, CSS-селектор, JSONPath); модель запускается только при изменении.
- **`event`** — входящие вебхуки `POST /hooks/<id>` с секретом; события шины.
- **`heartbeat`** — редкий обзор (по умолчанию 3 раза в день в рабочие часы).

Срабатывание создаёт задачу для агента: шаблон промпта + контекст события.

### 7.2 Уровни инициативы

`0` — только отвечает; `1` — предлагает (по умолчанию; фоновые задачи только с инструментами чтения); `2` — действует в рамках правил.

### 7.3 Решение «стоит ли беспокоить»

Фоновая задача завершается инструментом `notify({level, title, body})`: `silent` (только журнал), `digest` (в ближайшую сводку), `notify` (сразу в каналы), `ask` (нужен ответ). Ядро добавляет тихие часы, лимиты частоты на триггер, дедупликацию. Под проактивными сообщениями — кнопки «полезно / реже / выключить»; ответ меняет параметры триггера и сохраняется в память.

### 7.4 Бюджет

Дневные лимиты запусков (подписки) и токенов (API) на агента и триггер. Интерактивные запросы приоритетнее фоновых; при давлении лимитов фоновые задачи ставятся на паузу первыми.

### 7.5 Каналы

Интерфейс канала: приём сообщений в главный тред, отправка сообщений и уведомлений, отображение подтверждений с кнопками. MVP: веб и Telegram.

**Telegram:** long polling; привязка `/start <код>`; принимается один chat id; подтверждения — краткое описание + кнопки (данные кнопок подписаны HMAC и одноразовые), полный текст — ссылка на пульт; настройка «показывать детали в Telegram».

## 8. Браузер, MCP, скиллы, память

### 8.1 Браузер (плагин `browser`)

- Обычный браузер с постоянным профилем: установленный Google Chrome, иначе полный Chromium Playwright (не headless shell); headless, если нет дисплея.
- Для сайтов он выглядит как браузер человека: без `--enable-automation` и `navigator.webdriver`, окно своего размера (без эмуляции viewport), в headless — экран (`--screen-info`) и user agent без «Headless» (его называет сам браузер при первом запуске). Проверки, которые проходят сами (Cloudflare), `browser.open` пережидает, глядя на страницу только из изолированного мира Playwright: наш скрипт в мире страницы их ломает.
- Без Google Chrome плагин при старте проверяет его и, если нет, сам запускает `playwright install chromium` (CLI из node_modules, через egress-прокси с токеном плагина); браузерные вызовы ждут эту одну установку, неудачная повторяется при следующем вызове. `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` отключает автоустановку.
- Инструменты: `browser.open`, `browser.snapshot` (интерактивные элементы со ссылками `ref`), `browser.click`, `browser.type`, `browser.fill_secret` (vault-ссылка, значение печатает плагин), `browser.screenshot`, `browser.scroll`, `browser.tabs`, `browser.back`, `browser.download` (в карантин workspace).
- Живой экран: CDP `Page.startScreencast` → WebSocket → панель веба. Перехват: события мыши и клавиатуры из веба → `Input.dispatch*`; агент на паузе, пока управление у пользователя.
- Капчи агент не решает — просит перехватить управление.
- Все результаты браузера помечают сессию как `tainted`.

### 8.2 MCP

- Ядро — MCP-клиент для внешних серверов: stdio (процессы с egress-прокси) и Streamable HTTP. Конфиг — формат `.mcp.json`; значения вида `vault://id` подставляются ядром.
- Внешние инструменты попадают в MCP-шлюз под именами `<server>.<tool>` с классом из аннотаций.

### 8.3 Скиллы и команды

- Формат Agent Skills: папка с `SKILL.md` (frontmatter `name`, `description`).
- Источники: плагины, `/data/skills`. У агента — список включённых.
- Для `claude-code` скиллы раскладываются в `<workspace>/.claude/skills/`, для `codex` — в `<workspace>/.agents/skills/`; для `api` — имена и описания в системном промпте и инструмент `skill.load`.
- Команды (`commands/*.md`): `/имя аргументы` в чате разворачивается в промпт.

### 8.4 Память (плагин `memory`)

- Markdown-файлы в `/data/memory/`: `MEMORY.md` (индекс, попадает в системный промпт), `profile.md`, `people/`, `projects/`, `notes/`; один факт на файл с frontmatter.
- Папка под git, каждое изменение — коммит (если git доступен).
- Инструменты: `memory.search` (SQLite FTS5, иначе поиск по подстроке), `memory.read`, `memory.write`, `memory.forget`.
- Факты, записанные из помеченной (`tainted`) сессии, попадают в очередь «на проверку» и не входят в индекс до одобрения.

## 9. Сеть машин (`packages/node`)

- Демон `openbot-node`: `openbot-node pair <hub-url> <code>`, затем `openbot-node run`.
- Подключение: исходящий WebSocket `wss://hub/node/ws`, аутентификация подписью challenge.
- Возможности MVP: отчёт о машине (ОС, CLI и их версии/логины), запуск мозгов `claude-code`/`codex` локально (мост MCP подключается к хабу напрямую по `OPENBOT_URL`), инструменты `machine.exec` (`local-write`, подтверждение по умолчанию) и `machine.read_file`/`machine.write_file` в разрешённых папках.
- Хаб маршрутизирует сессии мозгов `<brain>@<machine>` на соответствующий демон; события сессии идут по тому же WebSocket.
- Связь через разные сети — Tailscale (документация).

## 10. Веб-интерфейс

**Основной (8080):** чат (главный тред, треды задач, карточки вызовов инструментов, вложения), лента задач, панель браузера (живой экран, перехват), агенты, плагины (установка из git/папки с подтверждением прав), триггеры, машины (привязка, статусы), память (просмотр, правка, очередь «на проверку»), настройки (провайдеры, мозги, тихие часы, бюджеты). Адаптивная вёрстка для телефона.

**Пульт безопасности (8081):** подтверждения, vault (разблокировка, записи, области), правила, аудит (с проверкой цепочки), входы и passkey.

## 11. Ошибки и устойчивость

- Задачи хранятся как машина состояний; после перезапуска хаба `running` → `interrupted` → автоматическое продолжение (resume мозга или сводка).
- Падение процесса мозга — до 3 перезапусков с экспоненциальной паузой, затем `failed` с причиной.
- CLI не залогинен — `probe` показывает инструкцию, задачи идут к следующему мозгу.
- Машина офлайн — ожидание до таймаута (по умолчанию 10 минут), затем следующий мозг.
- Падение плагина — перезапуск; 5 падений за 10 минут — плагин отключается с уведомлением.
- Подтверждение без ответа — напоминание через 1 час, автоотмена через 24 часа.
- Vault запечатан — задачи, требующие секретов, ждут; уведомление «разблокируй vault».
- Падение браузера — перезапуск с тем же профилем, повтор текущего шага один раз.
- Бэкап: `openbot backup` — архив `/data` (vault остаётся зашифрованным).

## 12. Тестирование

- **Юнит (Vitest):** политики, правила, taint, vault, редакция, манифесты и права, RPC, триггеры, cron, сравнение в вотчерах, хэш-цепочка аудита.
- **Контрактные тесты мозгов:** записанные потоки `stream-json`/`--json` воспроизводятся фейковыми CLI; периодический прогон на реальном `claude`.
- **Мок LLM-сервер** (Anthropic Messages + OpenAI Chat) для мозга `api` и сквозных сценариев.
- **Сквозные (Playwright):** старт хаба → ссылка настройки → пароль → чат → инструмент → подтверждение на пульте → результат; Telegram через мок Bot API.
- **Безопасность:** фикстуры prompt injection (страница/письмо пытается вытащить секрет, создать правило, отправить сообщение) → редакция/отказ/подтверждение; DNS rebinding (чужой Host); UI-код основной страницы не получает доступ к API пульта; плагин без прав не получает сеть/vault.
- **Публичный API:** встроенные плагины импортируют только `@openbot/plugin-sdk` и `@openbot/ui` (проверка в тестах).
- **CI:** GitHub Actions — lint, типы, тесты, установщики приложения и сервера (amd64/arm64).

## 13. Этапы

1. **M1 Ядро:** хаб, БД, хост плагинов, RPC, шина и хуки, веб-оболочка со слотами, каркас политик, мозг `api`, чат.
2. **M2 Безопасность:** vault, пульт (подтверждения, правила, аудит), вход (пароль, passkey), egress-прокси, редакция, taint.
3. **M3 Подписки:** мозги `claude-code` и `codex`, MCP-шлюз и мост, агенты, задачи, делегирование, скиллы, команды, внешние MCP.
4. **M4 Браузер:** плагин браузера, живой экран, перехват, `fill_secret`.
5. **M5 Проактивность:** Telegram, триггеры, `notify`, тихие часы, бюджеты, память.
6. **M6 Сеть машин и поставка:** демон, привязка, локальные политики, удалённые мозги; Docker-образ, entrypoint, документация.
