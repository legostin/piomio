# Auto mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** What used to be an approval card is decided by a reviewer model, as in Claude Code's auto mode; the person
keeps money, messages, publishing and the hub's own-card actions (spec: `docs/superpowers/specs/2026-11-02-auto-mode-design.md`).

**Architecture:** A fast path in `native-permissions.ts` (read-only commands, the agent's whole folder, denied paths
named in commands, a per-session folder grant) cuts most cards without a model. What still asks goes to
`AutoMode.decide` (`policy/auto.ts`): always-the-person detection, then a two-stage reviewer (`policy/reviewer.ts`)
running a bare Claude Code session, then block counters. `native_permission` and the gateway call it; a block is a
`blocked` approval drawn as a quiet line with "Allow".

**Tech Stack:** TypeScript on Node 24 (type stripping, `.ts` imports), vitest, React web UI, Claude Code CLI.

## Global Constraints

- Node ≥ 24 runs TypeScript directly; only erasable syntax; `import type` for types; local imports end in `.ts`.
- Every user-facing string goes through the en/ru catalogs; text for the model is English and not translated.
- Contracts (`packages/shared/src/types.ts`) change deliberately: `ApprovalStatus` gains `"blocked"`, `ApprovalVia`
  gains `"auto"`, `Approval` and the approval part gain `auto?: { rule: string; reason: string }`,
  `BrainSessionOptions` gains `bare?: boolean`.
- Tests write temp files only under `tmpdir()`.
- `approvalMode` default `"auto"`; a failed review gives a card, never a silent refusal.
