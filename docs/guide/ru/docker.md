Образ Docker — это Piomio со всем нужным: хаб, веб-интерфейс, пульт безопасности, встроенные плагины, официальные CLI Claude Code, Codex и Kimi Code, Chromium для браузера агентов и узел Tailscale для доступа из любого места. Это самая строгая изоляция, какая есть у Piomio: интеллект и плагины работают от отдельных пользователей, каждый в своих папках, а их сеть идёт через фильтр, который может держать само ядро. Смотри [Модель безопасности](security.md).

Нужен сервер на Linux (или любой компьютер) с Docker и Docker Compose, на amd64 или arm64. Без Docker — смотри [На сервере с Linux](server.md).

## Запуск

```bash
git clone https://github.com/legostin/piomio.git && cd piomio
docker compose up -d
docker compose logs piomio | grep -A1 "Piomio:"
```

Последняя команда покажет код установки, который ты введёшь при первом входе. Дальше [открой чат](#как-открыть) и пройди [первый запуск](#первый-запуск).

## Образ и его теги

`docker compose` берёт готовый образ `ghcr.io/legostin/piomio` с GitHub, собранный для linux/amd64 и linux/arm64. Какой именно, задаёт `PIOMIO_IMAGE_TAG` в `.env`:

| Тег | Что это |
|---|---|
| `latest` | последний релиз (по умолчанию) |
| `main` | каждое изменение основной ветки; ещё он пересобирается по понедельникам со свежими системными пакетами, CLI и Chromium |
| `0.2.12`, `0.2` | конкретный релиз или самый новый в линейке |

CLI в образе сами не обновляются: новые версии приходят с новым образом.

## Настройки: файл .env

Настройки пишутся в `.env` рядом с `docker-compose.yml`. Скопируй [.env.example](https://github.com/legostin/piomio/blob/main/.env.example), где каждая указана с примером, и раскомментируй нужные:

```bash
cp .env.example .env
```

Две из них читает сам `docker-compose.yml`: `PIOMIO_IMAGE_TAG` и `PIOMIO_BIND`. Остальные уходят в контейнер. После правки снова выполни `docker compose up -d`. Все переменные со значениями по умолчанию — в разделе [Переменные окружения](settings.md#переменные-окружения).

## Том с данными

Всё, что хранит Piomio, лежит в томе `piomio-data`, смонтированном в `/data`:

| Путь в `/data` | Что там |
|---|---|
| `piomio.db` | чаты, агенты, задачи, каналы, настройки |
| `vault.db` | хранилище секретов, зашифрованное твоим паролем хранилища |
| `home/agent` | домашняя папка CLI интеллекта: твои входы в Claude Code, Codex и Kimi Code |
| `home/plugin` | домашняя папка остальных плагинов и MCP-серверов |
| `workspaces` | рабочие папки агентов |
| `plugins`, `plugins-data` | установленные плагины и данные каждого плагина (включая память) |
| `agents`, `skills`, `commands` | агенты, скиллы и команды, которые ты создал |
| `pages` | страницы, которые сделали агенты |
| `tailnet` | ключи узла доступа из любого места |
| `devices` | сертификат, который запоминает приложение на телефоне |
| `backups` | резервные копии, сделанные командой `backup` |

Журнал хаба — это вывод контейнера: `docker compose logs -f piomio`.

## Как открыть

Чат (порт 8080) и пульт безопасности (порт 8081) опубликованы только на самом сервере, на `127.0.0.1`, так что в интернет ничего не смотрит.

### Через SSH

Ничего настраивать не нужно. На своём компьютере выполни и не закрывай:

```bash
ssh -N -L 8080:localhost:8080 -L 8081:localhost:8081 <пользователь>@<сервер>
```

Теперь http://localhost:8080 в браузере — это хаб, вместе с ключами доступа (passkeys). Номера портов по обе стороны должны совпадать: хаб принимает изменения только с известного ему адреса.

### По адресу сервера

Впиши в `.env` и выполни `docker compose up -d`:

```ini
PIOMIO_BIND=0.0.0.0
PIOMIO_PUBLIC_URL=http://<адрес>:8080
```

Без `PIOMIO_PUBLIC_URL` хаб отказывает всем адресам, кроме `localhost`. Это обычный HTTP без ключей доступа, а опубликованные порты Docker открывает в обход `ufw`. В открытом интернете ставь перед хабом HTTPS.

### HTTPS перед хабом

Если у тебя свой домен и обратный прокси на сервере (Caddy, nginx и похожие), оставь `PIOMIO_BIND=127.0.0.1`, направь прокси на `127.0.0.1:8080` и `127.0.0.1:8081` (вместе с WebSocket), дай пульту отдельный адрес и сообщи хабу:

```ini
PIOMIO_PUBLIC_URL=https://piomio.example.com
PIOMIO_CONSOLE_URL=https://console.piomio.example.com
PIOMIO_TRUST_PROXY=1
```

`PIOMIO_ALLOWED_HOSTS` добавляет другие имена, на которые хаб отвечает. Если на сервере есть Tailscale, HTTPS перед обоими портами может поставить `tailscale serve`; смотри [Доступ из любого места](anywhere.md).

### Откуда угодно

После настройки скажи в чате «включи доступ из любого места». Собственный узел Tailscale, который есть в образе, даст хабу постоянную HTTPS-ссылку. Смотри [Доступ из любого места](anywhere.md).

## Первый запуск

1. Открой чат, введи **Код установки** из журнала (его показывает и `docker logs piomio`) и придумай пароль. Язык твоего браузера станет языком хаба, если его не закрепил `PIOMIO_LANG`.
2. Пока ни один интеллект не работает, в чате висит карточка настройки. Нажми **Войти** у Claude Code, Codex или Kimi Code и войди на странице самого производителя со своим тарифом. Вход хранится в `/data/home/agent`; Piomio никогда не берёт и не хранит токены. Если хаб запущен с `PIOMIO_API_KEYS=1`, карточка примет и API-ключ. Смотри страницу [про интеллект и вход](brains.md).
3. Дальше ассистент ведёт остальную настройку в чате. Смотри [Первый запуск](first-run.md).

## Пользователи внутри контейнера

| Пользователь | Что запускает | Его папки |
|---|---|---|
| `piomio` | хаб | владеет `/data` |
| `agent` | CLI интеллекта (Claude Code, Codex, Kimi Code) | `/data/home/agent` |
| `plugin` | остальные плагины и MCP-серверы | `/data/home/plugin` и `/data/plugins-data/<плагин>` для каждого плагина |

Остальных хаб запускает через `sudo` и передаёт каждому только нужные ему переменные. Рабочие папки агентов принадлежат группе `piomio`, в которой состоит `agent`, поэтому интеллект может там писать; база и хранилище принадлежат только `piomio`.

## Фильтр исходящих соединений

Интеллект и плагины выходят в сеть только через прокси хаба на `127.0.0.1:8089`, у каждого свой список разрешённых адресов:

- Интеллекту можно к своим производителям (Anthropic, OpenAI, Kimi), на GitHub, в npm, PyPI и похожие места, плюс **Дополнительные разрешённые хосты** в **Настройки → Общие**.
- Плагину можно к хостам, которые названы в его разрешениях.
- Адреса в частных сетях (твоя локальная сеть, `localhost`) закрыты, если хоста нет в `egressPrivateAllow`; смотри [Настройки без поля](settings.md#настройки-без-поля).

По умолчанию (`PIOMIO_EGRESS_ENFORCED=proxy`) программам велят ходить через прокси, и программа, которая это проигнорирует, всё ещё может подключиться напрямую. Чтобы это запрещало ядро, раскомментируй `cap_add: [NET_ADMIN]` в `docker-compose.yml`, впиши в `.env` и выполни `docker compose up -d`:

```ini
PIOMIO_EGRESS_ENFORCED=iptables
```

Тогда `agent` и `plugin` достают только до loopback (прокси и хаб) и DNS. В журнале появится `egress enforced with iptables`. Без этой возможности контейнера будет предупреждение `iptables unavailable`, и останется только прокси.

## Хранилище открывается само

После перезапуска хранилище запечатано, пока ты его не откроешь. Сделать, чтобы оно открывалось само, можно двумя способами:

- **В чате.** На карточке хранилища оставь включённым **Открывать автоматически после перезапуска (пароль хранится на этом сервере)**. Пароль ляжет в `/data/vault.passphrase`, который может прочитать только хаб.
- **Своим файлом**, например секретом Docker. Положи рядом с `docker-compose.yml` файл `docker-compose.override.yml` (Compose читает его сам):

  ```yaml
  services:
    piomio:
      secrets:
        - piomio_vault
  secrets:
    piomio_vault:
      file: ./vault-passphrase.txt
  ```

  а в `.env`:

  ```ini
  PIOMIO_VAULT_PASSPHRASE_FILE=/run/secrets/piomio_vault
  ```

Файл должен быть на месте, когда хаб запускается, и читаться пользователем `piomio` внутри контейнера. Если хранилища ещё нет, пароль из файла его создаст. Если открыть не вышло, в журнале будет `[vault] auto-unlock failed`.

## Телефоны

Приложение на телефоне говорит с хабом через собственный HTTPS-порт, внутри контейнера это 8082. Внутри Docker хаб видит только адреса контейнера, до которых телефону не достать. Чтобы подключать телефон по своей сети, опубликуй порт (раскомментируй `- "8082:8082"` в `docker-compose.yml` или добавь его в файл override) и перечисли в `.env` адреса, по которым телефонам ходить:

```ini
PIOMIO_DEVICE_URLS=https://192.168.1.10:8082
```

Без этого телефоны ходят по ссылке [доступа из любого места](anywhere.md). Чтобы подключить телефон, скажи в чате «подключи мой телефон» или открой **Настройки → Устройства** и нажми **Подключить телефон**. Смотри [Приложение для iPhone](phone.md).

## Браузер

Chromium уже в образе. Он работает с настоящим окном на виртуальном дисплее внутри контейнера, поэтому сайты видят обычный браузер, а скриншоты выглядят как настоящие. Chromium нужна общая память: оставь `shm_size: 1gb` из `docker-compose.yml` (с обычным `docker run` — `--shm-size=1g`). Смотри страницу [про браузер и режим обучения](browser.md).

## Команды контейнера

```bash
docker exec piomio piomio-entrypoint reset-password 'новый-пароль'
docker exec piomio piomio-entrypoint backup
docker exec piomio piomio-entrypoint audit-verify
```

- `reset-password` задаёт новый пароль (от 8 символов) и завершает все сессии.
- `backup` копирует базу, хранилище (по-прежнему зашифрованное), агентов, скиллы, команды, плагины и их данные в `/data/backups/<дата и время>`. Папка после команды кладёт копию туда; каждый раз бери новую пустую. В копию не попадают рабочие папки, страницы и входы CLI.
- `audit-verify` проверяет цепочку хешей журнала аудита и выходит с кодом 2, если она нарушена.

Копия в томе пропадёт вместе с томом, так что забирай её наружу:

```bash
docker cp piomio:/data/backups ./piomio-backups
```

Другие повседневные команды: `docker compose logs -f piomio` (журнал), `docker compose restart piomio` (перезапуск), `docker compose ps` (проверка здоровья показывает, отвечает ли хаб).

## Обновление

```bash
git pull && docker compose pull && docker compose up -d
```

`git pull` приносит свежий `docker-compose.yml`, `docker compose pull` — свежий образ твоего тега. Кнопка **Обновить** из приложения для компьютера и установки на сервер для Docker не работает: хаб так и скажет, если попросить. Если в `PIOMIO_IMAGE_TAG` закреплена версия, сначала поменяй её там. Смотри [Обновления](updates.md).

## Своя сборка образа

```bash
docker compose up -d --build
```

Так образ собирается из склонированной папки, а не скачивается. Сборка компилирует веб-интерфейс и узел Tailscale и скачивает CLI и Chromium, поэтому занимает время. Без Compose: `docker build -f docker/Dockerfile -t piomio .` из корня репозитория.

## Удаление

`docker compose down` останавливает и удаляет контейнер; том `piomio-data` со всеми данными остаётся. `docker compose down -v` удаляет и том: чаты, хранилище, входы, всё. Это не отменить, так что сначала сделай резервную копию и забери её наружу.
